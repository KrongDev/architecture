# 모놀리식 아키텍처란?

모놀리식 아키텍처(Monolithic Architecture)는 소프트웨어 시스템을 하나의 통합된 애플리케이션으로 개발하는 아키텍처 스타일을 의미합니다. 일반적으로 하나의 코드베이스와 하나의 빌드 시스템을 가지며, 모든 기능이 단일 애플리케이션 내에서 실행됩니다.

## 모놀리식 아키텍처의 특징

1. **단일 코드베이스**: 애플리케이션의 모든 기능이 하나의 코드 저장소에서 관리됩니다.
2. **통합된 배포**: 하나의 애플리케이션으로 빌드되고 배포됩니다.
3. **단일 데이터베이스**: 대부분 하나의 데이터베이스를 사용하여 데이터를 관리합니다.
4. **모든 기능이 같은 프로세스 내에서 실행**: 클라이언트 요청이 들어오면 하나의 애플리케이션 내에서 처리됩니다.

## 모놀리식 아키텍처의 장점

1. **간단한 개발 및 배포**
    - 한 번의 빌드 및 배포로 모든 기능이 업데이트됨
    - 코드 구조가 비교적 단순하여 개발 및 디버깅이 용이함

2. **일관된 성능**
    - 모든 기능이 같은 프로세스에서 실행되므로 네트워크 통신 오버헤드가 적음

3. **트랜잭션 관리 용이**
    - 하나의 데이터베이스를 사용하므로 복잡한 분산 트랜잭션 관리가 필요 없음

4. **운영 및 모니터링 용이**
    - 하나의 애플리케이션이므로 관리할 서비스가 적어 모니터링과 로깅이 쉬움

## 모놀리식 아키텍처의 단점

1. **규모 확장 어려움**
    - 애플리케이션 크기가 커질수록 빌드 및 배포 시간이 증가
    - 특정 기능만 확장하는 것이 어렵고 전체 애플리케이션을 확장해야 함

2. **부분적인 기술 스택 변경 어려움**
    - 특정 모듈만 새로운 기술을 적용하는 것이 어려움
    - 전체 애플리케이션을 수정해야 하는 경우가 많음

3. **개발 생산성 저하**
    - 코드베이스가 커질수록 새로운 기능 추가 및 유지보수가 어려워짐
    - 팀 간 협업이 어려워질 수 있음

4. **배포 리스크 증가**
    - 작은 변경 사항도 전체 시스템 재배포가 필요함
    - 하나의 오류가 전체 시스템에 영향을 줄 수 있음

## 모놀리식 아키텍처의 사용 사례

모놀리식 아키텍처는 초기 스타트업이나 소규모 프로젝트에서 주로 사용됩니다. 대표적인 사례로 다음과 같은 경우가 있습니다.

- **초기 스타트업**: 빠른 개발과 배포가 필요할 때
- **사내 시스템**: 트래픽이 크지 않고, 유지보수가 상대적으로 쉬운 내부 시스템
- **기능이 명확하고 변경이 적은 애플리케이션**

하지만 일정 규모 이상의 서비스가 되면 마이크로서비스 아키텍처로 전환을 고려하는 것이 일반적입니다.

## 개인 생각
모놀리식 아키텍처는 적당한 규모의 프로젝트에서는 매우 효율적인 아키텍처라 생각합니다.  
다만, 위 글에서 말했듯 확장성에 있어 프로젝트가 거대화 되는 염려가 생길 것이고, 유연성의 한계가 있어 지속적인 유지보수 즉 발전하는 형태의 유지보수를 하기에는 적합하지 않다 생각하는 아키텍처입니다.
